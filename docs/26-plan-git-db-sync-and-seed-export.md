# Plan: Git-Based DB Sync + Seed Export

## Context
The DB file (`db/command-center.db`) is already tracked in git (`.gitignore` lines are commented out). The goal is to make pulling the repo on any machine give you the current DB state instantly, with no manual steps beyond `git pull`. Three gaps exist:
1. WAL sidecar files must be checkpointed before commits or the `.db` file is incomplete
2. No script exports current DB state back into the seed files (seeds drift from reality)
3. No post-pull automation to apply pending migrations

## Two-Layer Sync Strategy
- **Primary**: commit the `.db` file itself â€” pull on any machine = instant current data
- **Fallback**: seed scripts regenerated from live DB â€” can rebuild from scratch if DB is corrupted

## Step 1 â€” `scripts/checkpoint-db.ts`
Extracts the inline WAL checkpoint one-liner from `rebuild-image.md` into a proper reusable script:

```ts
import Database from "better-sqlite3";
import path from "path";

const dbPath = path.join(process.cwd(), "db", "command-center.db");
const db = new Database(dbPath);
db.pragma("wal_checkpoint(TRUNCATE)");
db.close();
console.log("WAL checkpointed.");
```

## Step 2 â€” `scripts/export-seeds.ts`
Reads the live DB and regenerates all three seed files. Reuses `better-sqlite3` directly (same pattern as `db/seed-settings-project.ts`). Uses `JSON.stringify()` for all string values to handle escaping safely.

**What it regenerates:**

### `db/seed.ts` (feed sources)
- Reads all rows from `feed_sources` ORDER BY id
- Generates an array literal with `name, url, type, adapter, topicTags, active`
- Uses upsert (insert OR update) so toggling a feed active/inactive propagates when teammates pull
- Sets `staleUrls: string[] = []` (DB is already clean at export time)
- Adds `// AUTO-GENERATED by scripts/export-seeds.ts` header

### `db/seed-projects.ts` (all projects + items)
- Reads ALL non-archived projects + their items from DB
- Generates a unified `projectDefs` array covering Command Center, Settings, and any others
- Each project entry: `{ name, description, items: [{ title, notes, status, tags, sort_order }] }`
- Uses upsert-by-title pattern (same as existing file) â€” safe to run repeatedly
- Adds `// AUTO-GENERATED` header

### `db/seed-settings-project.ts` (compat shim)
Settings project data is now in `seed-projects.ts`. Rewrite as a one-liner shim:
```ts
console.log("Settings project is now seeded by db/seed-projects.ts â€” run: npm run seed:projects");
```

### `db/seed-settings.ts` (NEW â€” generated)
- Reads `settings` table, excludes `last_fetched_at` (runtime state)
- Generates upsert array: `[{ key, value }]`
- Uses `ON CONFLICT(key) DO UPDATE SET value = ...` â€” propagates user config changes across machines

## Step 3 â€” `package.json` â€” Add `db:*` scripts

```json
"db:checkpoint":   "npx tsx scripts/checkpoint-db.ts",
"db:export-seeds": "npx tsx scripts/export-seeds.ts",
"db:pull-sync":    "npx drizzle-kit migrate",
"db:commit":       "npm run db:checkpoint && git add db/",
"seed:settings":   "npx tsx db/seed-settings.ts"
```

`db:commit` checkpoints + stages all of `db/` (`.db`, `.db-wal`, `.db-shm`, seed files). User still writes the commit message.

## Step 4 â€” `.githooks/pre-commit`
Auto-checkpoint before every commit so `.db` is always complete:

```sh
#!/bin/sh
if [ -f "db/command-center.db" ]; then
  echo "[pre-commit] Checkpointing WAL..."
  npx tsx scripts/checkpoint-db.ts
  git add db/command-center.db db/command-center.db-wal db/command-center.db-shm 2>/dev/null || true
fi
```

## Step 5 â€” `.githooks/post-merge`
Auto-apply migrations after `git pull`:

```sh
#!/bin/sh
echo "[post-merge] Applying pending DB migrations..."
npx drizzle-kit migrate
echo "[post-merge] Done."
```
