## Lunch conversation (agentic AI focus)
-contacts: Ford Prior, Custom llm writer (Andrew Novokhatny)
- almost no-one was using AI for production level code
- the only example provided of production level was AI supporting the call center support agents. Faster and better support provided without the user needing to interact directly with ai
- Low trust in AI currently. Gained over time by seeing mistakes, hallucinations, etc.
- Good discussion about agents and their roles- hierarchical context and direction could allow more autonomous development
- short term implications of ai- developers hardly ever need to code. They should be architecting and providing solutions via ai. 
- long term - no-one really had an answer or idea for this. I felt like there was a real fear that if the models continue to grow the way they have been, there's no reason the ai agents themselves could architect...
- Economy of AI - we're nearing an inflection point where the cost of running a network of agents is going to be too high for feasibility. We are already at the point where token usage can exceed feasibility
- Some discussion around proper use for AI: Use the butter knife, not the chainsaw: ex. Feeding data directly to ai for extraction instead of scripting, extracting, and feeding that stripped data for analysis
- Discussion about custom llms. Journal entry speaker was there, used an apple m4 with 24gb ram to develop his model. It can definitely write like him but the parameters are that he feeds bullet points so it's not creating new content without prompting with specific information
-Talked about using ollama llm locally hosted and teaching it how to code like me/you as the developer, hooking into that with Claude Code/MCP, to solve and create code in a specific fashion. Data to feed and train the model is limited but has potential.
